    **Multi-contour fusion approach:**

    Instead of selecting the single best contour, fuse the top-N contour candidates' meniscus positions to get a more robust estimate.

    **Step 1: Return top-N scored contours**

    Modify `scoring.ts` — add a new function:
    ```typescript
    export interface ScoredContours {
      all: Array<{ idx: number; score: number; meniscusY: number; edgeStrength: number }>;
      best: ScoredContour | null;
    }

    /**
     * Scores ALL contours and returns top-N (default N=3) sorted by score descending.
     * Still applies the minScoreThreshold filter.
     */
    export function scoreContoursTopN(
      contours: ContourRect[],
      imageWidth: number, imageHeight: number,
      n: number = 3,
    ): ScoredContours { ... }
    ```

    Keep `scoreContours()` unchanged for backward compatibility.

    **Step 2: Implement weighted fusion in `contour.ts`**

    In `detectMeniscus()`, after contour scoring:

    1. Get top-3 scored contours (with their original OpenCV contour objects)
    2. For each contour, independently detect its meniscus Y (same `findHorizontalEdges` approach)
    3. Compute weighted average of meniscus positions, weighted by each contour's score:
       ```
       fusedMeniscusY = Σ(meniscusY_i * score_i) / Σ(score_i)
       ```
    4. Compute fused edge strength and meniscus ratio from the fused position
    5. If fewer than 2 contours pass the threshold → fall back to best-contour logic

    **Step 3: Evaluate fusion on edge-case corpus**

    ```bash
    tsx src/eval/cv-eval.ts worker/test/fixtures/cv-edge-eval/manifest.json 2>&1 | tee runs/heuristic-tuning/fusion-eval.txt
    ```

    Compare against Task 2 results:
    - Does fusion improve empty↔full confusion?
    - Does fusion improve exact accuracy?
    - Does fusion reduce "no_contour" miss reasons?

    **Step 4: Evaluate on holdout set**

    If fusion improves edge-case results, validate on the holdout set:
    ```bash
    tsx src/eval/cv-eval.ts worker/test/fixtures/holdout/manifest.json 2>&1 | tee runs/heuristic-tuning/holdout-fusion.txt
    ```

    **Trade-off documentation:**
    Fusion adds ~2-3× contour processing overhead. Measure the latency impact:
    ```bash
    tsx src/eval/cv-eval.ts worker/test/fixtures/cv-edge-eval/manifest.json 2>&1 | Select-String -Pattern "Latency"
    ```

    **Decision:**
    - If fusion → better edge-case results AND holdout results don't regress → KEEP fusion
    - If fusion → no improvement or holdout regresses → REVERT to single best-contour from Task 2
    - Document the decision and rationale in `runs/heuristic-tuning/fusion-decision.md`

    **What to avoid:**
    - Do NOT change the existing `scoreContours()` function signature (backward compat)
    - Do NOT use fusion if it doesn't measurably improve edge-case accuracy
    - Do NOT commit fusion code that regresses holdout accuracy
    - Do NOT skip the latency measurement — fusion must be practical for real-time use
    - Do NOT add more than top-3 fusion — diminishing returns beyond 3 contours
